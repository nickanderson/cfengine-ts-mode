#+TITLE: cfengine-ts-mode

Tree-sitter major mode for [[https://cfengine.com][CFEngine]] 3 policy in Emacs 30+.

It uses [[https://github.com/olehermanse/tree-sitter-cfengine][tree-sitter-cfengine]], the same grammar behind ~cfengine format~, ~cfengine lint~ and the [[https://github.com/olehermanse/zed-cfengine][Zed extension]]. Highlighting follows the Zed extension's =highlights.scm=; indentation matches ~cfengine format~.

* Features

- Font lock, including ~$(var)~ and ~@(list)~ references inside strings
- Indentation that agrees with ~cfengine format~, including while typing: new lines and incomplete blocks are indented from the surrounding text, ~:~, ~;~ and ~}~ reindent the line, and a comment moves to match the code typed after it
- Imenu and defun navigation (~C-M-a~, ~C-M-e~) over bundles, bodies and custom promise types, and ~which-function-mode~ shows the current one
- Sentence movement (~M-a~, ~M-e~) by promise, and by attribute in bodies
- ~outline-minor-mode~ folds blocks, and the sections (~vars:~, ~files:~, ...) inside bundles
- Completion of built-in function names and ElDoc signatures, from =cfengine.el=. These use your installed ~cf-promises~ (~cfengine-cf-promises~), falling back to built-in data
- Completion from the ~cf-promises~ syntax description: promise types valid for the bundle's type (adding the ~:~), attributes of the section's promise type or the body's type (adding ~=>~), option values such as ~"true"~, and the names of bodies and bundles of the right type from the buffer and its policy tree. ElDoc shows an attribute's type and allowed values on its name and while typing its value. These need ~cf-promises~
- Recognizes CFEngine policy by content. =.cf= is shared with Postfix and sendmail, so a =.cf=, =.cf.sub=, =.cf.in= or =.cf.sub.in= file opens as CFEngine only if it contains a ~bundle~, ~body~ or ~promise~ block header
- Remaps ~cfengine-mode~ and ~cfengine3-mode~ when the grammar is installed, so Org src blocks in ~cfengine3~ use it too. Without the grammar, policy files open in ~cfengine3-mode~
- ~M-x compile~ runs ~cf-promises -f~ on the current file
- ~M-x cfengine-ts-mode-format-buffer~ formats with ~cfengine format~, replacing only what changed so point and marks stay put. Set ~cfengine-ts-mode-format-on-save~ to do it on every save; a file that doesn't parse is still saved, unformatted
- ~M-x cfengine-ts-mode-format-region~ formats the bundle, body and promise blocks a region touches, or the block at point without an active region. ~cfengine format~ only accepts complete policy, so it works on whole blocks; a block formatted alone comes out the same as when its whole file is formatted. To fix only indentation in any region, use ~indent-region~ (~C-M-\~)
- A Flymake backend for ~cfengine lint~; turn on ~flymake-mode~ to use it. Inside a policy tree (a parent directory with =promises.cf= or =promises.cf.in=, as in masterfiles), the buffer is linted with the tree's other policy files in strict mode, so bundles and bodies from the standard library resolve and deprecations and naming conventions are reported. Elsewhere it is linted on its own with strict mode off
- Registered as a child of ~cfengine3-mode~, so its hooks, snippets and keybindings still apply

* Installation

#+begin_src emacs-lisp
(use-package cfengine-ts-mode
  :vc (:url "https://github.com/nickanderson/cfengine-ts-mode"))
#+end_src

Then build the grammar once (needs a C compiler and git):

: M-x cfengine-ts-mode-install-grammar

No ~auto-mode-alist~ setup is needed.

** Opting out of detection by content

The package adds an entry to ~magic-mode-alist~, which Emacs consults before ~auto-mode-alist~. It looks at the first 4000 characters of a =.cf=, =.cf.sub=, =.cf.in= or =.cf.sub.in= file and opens it in ~cfengine3-mode~ (remapped to ~cfengine-ts-mode~) if it finds a block header: a line holding only ~bundle~, ~body~ or ~promise~, a type and a name, optionally followed by a parameter list, ~{~ and a comment (~bundle agent main(x) {~). Keywords are case-sensitive, as in CFEngine. Against masterfiles and core's acceptance tests, this misses only files with no block at all.

To turn that off and decide by file name yourself, remove the entry after the package is activated, for example in ~:config~:

#+begin_src emacs-lisp
(setq magic-mode-alist
      (delete '(cfengine-ts-mode-policy-file-p . cfengine3-mode)
              magic-mode-alist))
;; Then, if you want, map files by name instead:
(add-to-list 'auto-mode-alist '("/masterfiles/.*\\.cf\\'" . cfengine-ts-mode))
#+end_src

|-----------+---------------------------------------------------------------------------------------------------------|
| ~C-c C-f~ | ~cfengine-ts-mode-format-buffer~                                                                        |
| ~C-c C-r~ | ~cfengine-ts-mode-format-region~ (the block at point without a region)                                  |
| ~C-c C-j~ | ~cfengine3-reformat-json-string~                                                                        |

* Customization

- ~cfengine-ts-mode-indent-offset~ (default 2)
- ~treesit-font-lock-level~ selects how much is highlighted (levels 1-4)
- ~cfengine-ts-mode-cfengine-program~ is the CFEngine CLI to run (default ~cfengine~)
- ~cfengine-ts-mode-format-on-save~ (default off)
- ~cfengine-ts-mode-lint-arguments~ adds arguments to ~cfengine lint~
- ~cfengine-ts-mode-docs-version~ is the documentation version ~C-c C-d~ opens: ~"lts"~ (default), ~"master"~ or a published version such as ~"3.24"~

** How linting picks its context

The rest of the policy tree is every =.cf= file under the policy root, skipping hidden directories (git worktrees can hold whole copies of the tree) and =tests= and =documentation= (their examples define bundles that clash with the real ones). If lint stops before reaching the buffer, usually because another file in the tree doesn't parse, the buffer is linted on its own instead, with a note on line 1 naming the problem.

A cfbs project's source tree doesn't contain the standard library, so it is linted on its own.

* Development

#+begin_src sh
make grammar   # build the grammar into .treesit/
make           # byte-compile, checkdoc, ERT tests
make corpus MASTERFILES=~/src/masterfiles   # reindent all of masterfiles
#+end_src

Use ~EMACS=/path/to/emacs~ to test against a specific build. The indentation test strips all indentation from =test/indent.cf=, reindents, and compares; that fixture must stay unchanged under ~cfengine format~. ~make corpus~ does the same for every policy file in a masterfiles checkout, after running ~cfengine format~ on copies.
